# M1.6.2 — Performance Benchmarks

Criterion benchmarks cover the four M1.6.2 targets: message bus adapter, FlatBuffers serialization layer, state machine throughput, and CLI startup (argument parsing).

## Run

```bash
# Core: serialization, state machine, Zenoh adapter (mock)
cargo bench -p mimi-core

# CLI: auth/token benches (existing) + startup parsing
cargo bench -p mimi-cli
```

## Suites

| Bench file | Package | What it measures |
|------------|---------|------------------|
| `serialization_benchmarks.rs` | mimi-core | `MessageSerializer` encode/decode at 64B–256KB payloads |
| `state_machine_benchmarks.rs` | mimi-core | FSM happy-path transitions; priority queue enqueue/dequeue |
| `zenoh_bus_benchmarks.rs` | mimi-core | `ZenohBusAdapter` create, subscribe, publish (mock bus) |
| `cli_benchmarks.rs` / `auth_benchmarks.rs` | mimi-cli | Auth token and permission hot paths (M1.4.8) |
| `startup_benchmarks.rs` | mimi-cli | `Cli::try_parse_from` for common commands |

HTML reports are written under `target/criterion/` when using the default Criterion configuration.

## Notes

- Zenoh benches use the in-tree mock adapter until the live Zenoh client is wired for production paths.
- Compare results on the same machine and Rust profile (`--profile bench` in workspace `Cargo.toml`).
