# M2.1 — Neo4j Environment & Schema

## Instance (M2.1.1)

Neo4j 5.15 Community runs in `docker-compose.yml` as `mimi-neo4j`.

- Browser: `http://localhost:7474`
- Bolt: `bolt://localhost:7687`
- Default credentials: `neo4j` / `mimi-password` (change in production)

## Graph model (M2.1.2)

| Label | Purpose | Key properties |
|-------|---------|----------------|
| `Context` | Memory node / session context | `id`, `label`, `content_hash`, `heat`, `last_accessed`, `access_count` |
| `Skill` | Executable capability | `id`, `name`, `version`, `status`, `runtime` |
| `Parameter` | Skill input | `id`, `name`, `type`, `required` |
| `Resource` | External doc or asset | `id`, `resource_type`, `uri` |
| `Metadata` | System or tenant metadata | `id`, `kind`, `version` |

| Relationship | Meaning |
|--------------|---------|
| `HAS` | Ownership (Metadata→Context, Context→Skill) |
| `EXECUTES` | Skill binds parameters |
| `DEPENDS_ON` | Skill requires resource |
| `REFERENCES` | Context links to resource |

Heatmap fields align with `planning/specs/HEATMAP-ALGORITHM.md` (`heat`, `last_accessed`).

## DDL (M2.1.3)

File: `docker/neo4j/schema.cypher`

Constraints: unique `id` per label; indexes on `heat`, `last_accessed`, `status`, `resource_type`.

Neo4j **Community** does not support property-existence constraints; those are omitted from `schema.cypher`.

## Seed (M2.1.4)

File: `docker/neo4j/seed.cypher` — bootstrap context, `echo` skill, sample resource.

Apply both:

```bash
./scripts/neo4j-apply-schema.sh
```

## Verification

```bash
docker exec -it mimi-neo4j cypher-shell -u neo4j -p mimi-password \
  "MATCH (c:Context) RETURN c.id, c.heat LIMIT 5;"
```

## Migration strategy

1. Version metadata node (`Metadata.version`).
2. Add new constraints with `IF NOT EXISTS`.
3. Backfill properties with `MATCH ... SET` in transactional batches.
4. Document breaking changes in release notes.
