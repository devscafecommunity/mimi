# M3.2 — Odlaguna watchdog

## States

`Idle` → `Monitoring` → (`Alerting` / `Intervention`) → `Idle`

Implemented in `mimi_core::OdlagunaWatchdog`.

## API

```rust
use std::time::Duration;
use mimi_core::OdlagunaWatchdog;

let mut wd = OdlagunaWatchdog::new();
wd.register_task("skill-run-1", Duration::from_secs(30));
// ... poll in executor loop
for id in wd.poll_expired() {
    // terminate container / escalate (Ryzu M3.1)
}
wd.complete_task("skill-run-1");
```

Audit events use tracing target `odlaguna.audit`.

## Worker heartbeat (M3.2.5)

Set `heartbeat_interval_secs` on `SkillRunRequest` (or `MIMI_HEARTBEAT_INTERVAL` in the worker). The runtime kills the container with `SkillRunStatus::HeartbeatLost` if `mimi-heartbeat` lines stop appearing in logs.

## Resource limits (M3.2.4)

While a container runs, `ryzu-runtime` polls Docker stats (`cgroup.rs`). If RAM or CPU exceeds `ResourceLimits`, the container is killed and the run returns `SkillRunStatus::ResourceExceeded` (in addition to static Docker `HostConfig` caps).

## Audit trail (M3.2.6)

On `poll_expired`, `intervene_expired_containers_with` calls `emit_intervention_side_effects`:

- **Neo4j:** `PandoraClient::record_odlaguna_intervention` → node `:OdlagunaAudit` (see `docker/neo4j/schema.cypher`)
- **In-memory:** `PandoraClient::odlaguna_audit_log()`

`mimi exec` passes `InterventionContext { pandora, zenoh }` so timeouts during AI runs are persisted when Pandora is available.

## Zenoh `mimi/task/timeout` (bus baseline)

`ZenohBusAdapter::publish_task_timeout` is invoked for each expired lease when a Zenoh adapter is wired into `InterventionContext`. Enable on the CLI with `MIMI_ZENOH=1` (mock bus logs `target=zenoh.bus` until real Zenoh is plugged in).

## Global supervisor (daemon / exec)

`OdlagunaSupervisorLoop` polls `odlaguna_global()` every `ODLAGUNA_TICK_MS` (default 100ms), runs audit/bus hooks, and kills containers when `docker-kill` is enabled. Leases are mirrored from `odlaguna_deadline` while the loop is active.

```bash
# Long-running process (flush + supervisor)
cargo run -p mimi-cli -- daemon

# Isolated Docker skills start a scoped supervisor (stops when the run ends)
cargo run -p mimi-cli --features docker-supervision -- debug skill-run --cmd echo hi
```

Env: `MIMI_ODLAGUNA_SUPERVISOR=1`, `MIMI_DAEMON=1` (set by `mimi daemon`), `MIMI_ZENOH=1`.

## Zenoh (native)

Build with `mimi-cli` feature `zenoh-bus` (`mimi-core/zenoh-bus`). Configure `ZENOH_MODE`, `ZENOH_CONNECT`, `ZENOH_LISTEN` (comma-separated endpoints). Without the feature, `MIMI_ZENOH=1` uses the mock publisher.

## Priscilla T3.6

`PriscillaAdvisor::critique_with_pandora` merges Pandora `query_failure_patterns` (Neo4j `:OdlagunaAudit` + in-memory audit). CLI: `mimi debug priscilla-critique --text "..." --with-patterns`.
